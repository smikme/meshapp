# Сборка и публикация через GitHub

Выпуск использует GitHub Actions, Releases, Pages и Secrets. Облачный RPC
`cloud.meshapp.privatepractice.app` и загрузка файлов `d.privatepractice.app`
продолжают работать независимо от выпуска. Сервер Gitea не используется.

## Первоначальная настройка

1. Добавить изменения в `main` репозитория `smikme/meshapp`. Workflow с ручным
   запуском должен присутствовать в основной ветке.
2. Публичный ключ `config/update-public-key.pem` хранится в Git и встраивается в
   приложение. Приватный ключ находится в `.release-secrets/update-private-key.pem`;
   каталог исключён из Git. Сохраните отдельную резервную копию. Новый ключ для
   каждого выпуска не нужен: установленные приложения доверяют прежнему.
3. Установить GitHub CLI, авторизоваться с правами администратора репозитория и
   выполнить из корня проекта:

   ```sh
   gh auth login
   bash scripts/ci/configure-github.sh
   ```

   Команда создаёт environment `production`, разрешает публикацию из `main`,
   сохраняет секрет `MESHAPP_UPDATE_ED25519_PRIVATE_KEY` и включает Pages с
   источником GitHub Actions. Она не публикует приложение.

   При ручной настройке: Settings → Environments → production → Secrets;
   Settings → Pages → Build and deployment → Source: GitHub Actions.
   Если для `github-pages` настроены ограничения веток, разрешите `main`.
4. Разрешить GitHub Actions в репозитории и сделать задания `Check` обязательными
   для слияния PR. Права записи релиза и Pages выделены только своим заданиям.

`scripts/ci/generate-update-key.sh` нужен только для создания первой пары в новом
проекте. Он отказывается перезаписывать существующие ключи. Старые ключи и
сертификаты не требуются. Developer ID и notarization в CI не настроены.

## Ежедневная работа

`Check` запускается для pull request, изменений `main` и вручную. Java-тесты
выполняются на Linux, Windows и macOS; сценарии публикации — на Linux с OpenSSL 3.
JUnit-отчёты сохраняются как Actions artifacts, в том числе при ошибке тестов.

Используются Temurin 25.0.5+8, Gradle Wrapper 9.8.2 с проверкой SHA-256,
appimagetool 1.9.1 с проверкой SHA-256 и Freedesktop runtime/SDK 25.08 для Flatpak.
Обновление инструментов делается отдельным изменением с проверкой всех платформ.

## Собрать выпуск

Actions → **Build release** → Run workflow, ветка `main`, версия, например
`2.4.0`. Допускаются `X.Y.Z` и `vX.Y.Z`: major/minor до 255, patch до 999.
Код версии: `major * 1000000 + minor * 1000 + patch`. Он одинаков для всех
платформ и повторных сборок. Непомеченные dev-сборки получают код 0.

Workflow фиксирует SHA коммита, запускает тесты и собирает:

| Платформа | Пакеты |
| --- | --- |
| Linux x86_64, Ubuntu 22.04 | DEB, AppImage, Flatpak, self-update ZIP |
| Windows x86_64, Windows 2022 | MSI, self-update ZIP |
| macOS aarch64, macOS 15 | DMG, self-update ZIP |
| macOS x86_64, macOS 15 Intel | DMG, self-update ZIP |

После `verifySelfUpdatePackage` файлы получают имена с версией, ОС и архитектурой.
Проверяются версия и публичный ключ внутри каждого ZIP. Только полный комплект
попадает в черновик GitHub Release вместе с `release.json` и `SHA256SUMS`.
Тег создаётся на SHA, из которого собраны пакеты.

Повторный запуск существующего тега допустим только с тем же SHA, пока релиз
остаётся черновиком. Опубликованные файлы не пересобираются. После изменения
исходников используйте следующую версию.

## Проверить и опубликовать

Скачать пакеты из черновика, проверить установку, первый запуск, BLE/USB и переход
между двумя версиями нового цикла обновлений. Linux-бинарники также проверить на
минимальной поддерживаемой системе. CI не заменяет тесты реального оборудования.
Mac DMG имеют ad-hoc-подпись: Gatekeeper может потребовать разрешение на запуск.

Отредактировать описание черновика. Затем Actions → **Publish release** → Run
workflow, ветка `main`, та же версия. Русские release notes можно указать отдельным
полем. Не публикуйте черновик кнопкой GitHub вручную: workflow сначала добавляет
подписанный манифест.

Публикация скачивает готовые файлы, сверяет SHA-256, размеры, SHA коммита,
встроенные версии и ключи. Секрет подписи должен соответствовать ключу сборки.
После проверки Ed25519-подписей workflow публикует релиз с `meshapp.json`, затем
разворачивает Pages. Адрес манифеста:
`https://smikme.github.io/meshapp/updates/stable/meshapp.json`.

Если Pages не развернулся после публикации, повторите **Publish release** с теми
же release notes. Новый манифест должен побайтово совпадать с опубликованным.
Продвижение релиза старее существующего стабильного запрещено. Исправления
доставляются следующей версией, без уменьшения `versionCode`.

## Каталог Lua, диагностика и Flatpak

Экспорты скриптов хранятся в `site/store/en/` и `site/store/ru/`. При публикации
генерируются `catalog.json` и адреса скачивания на Pages. Содержимого прежнего
магазина в проекте нет: каталог будет пустым до добавления экспортов `.json`
формата `meshapp-lua-script`. Данные Gitea не скачиваются. Каталог и документация
публикуются вместе с выпуском.

Диагностика сохраняется локально в `~/.meshapp/reports/`. Приложение открывает
форму GitHub Issue, но не отправляет отчёт. Пользователь проверяет архив и
прикрепляет его сам. Issue публичный; большие дампы памяти могут не поместиться
в ограничение вложений GitHub — тогда прикрепите отдельный лог из архива.
Токенов GitHub или Gitea в клиенте нет.

Flatpak публикуется как отдельный `.flatpak` bundle. Требуется Freedesktop
Platform 25.08 из Flathub; установка и обновление выполняются из скачанного
bundle. Собственный OSTree-репозиторий и SSH не используются.
`app.privatepractice.meshapp.yml` служит для локальной офлайн-сборки текущего
checkout; основной CI использует `./gradlew flatpak`.

Первый выпуск нового цикла устанавливается вручную. Старые клиенты не знают
нового адреса и ключа обновлений.

## Локальные проверки

```sh
python3 -m unittest discover -s scripts/ci/tests -v
./gradlew test
./gradlew jpackage selfUpdateArchive verifySelfUpdatePackage -PmeshappVersion=v2.4.0
```

Для AppImage и Flatpak добавьте инструменты и задачи в один вызов Gradle после
`jpackage`: задача `jpackage` очищает выходной каталог.
