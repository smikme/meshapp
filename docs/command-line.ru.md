# Запуск из командной строки

**Язык:** Русский | [English](command-line.md) | [Deutsch](command-line.de.md)

Без параметров MeshApp открывает обычное окно приложения. С параметром `--terminal` он работает в терминале (TUI), а с `--rpc-server` — как сервер, к которому можно подключиться из MeshApp на другом компьютере.

## Если приложение уже установлено

Откройте терминал и выполните команду для своей системы:

| Установка | Запуск TUI |
| --- | --- |
| Linux, пакет `.deb` | `/opt/meshapp/bin/MeshApp --terminal` |
| Linux, AppImage | `./MeshApp-v2.4.0-linux-x86_64.AppImage --terminal` |
| Linux, Flatpak | `flatpak run app.privatepractice.meshapp --terminal` |
| macOS | `/Applications/MeshApp.app/Contents/MacOS/MeshApp --terminal` |

Для AppImage подставьте имя скачанного файла. Если у него ещё нет права на запуск, добавьте его командой `chmod +x имя-файла.AppImage`.

Чтобы запустить RPC-сервер, замените `--terminal` на `--rpc-server`. Например, после установки `.deb`:

```bash
/opt/meshapp/bin/MeshApp --rpc-server --print-rpc-key
```

Параметр `--print-rpc-key` показывает ключ, который понадобится для подключения к серверу.

### Windows

Откройте PowerShell в папке, куда установлен MeshApp. Обычное приложение запускается командой `.\MeshApp.exe`, а RPC-сервер — так:

```powershell
.\MeshAppRpcServer.exe --print-rpc-key
```

Добавлять `--rpc-server` здесь не нужно. Файл `MeshAppRpcServer.exe` уже предназначен для запуска сервера.

Для TUI используйте `runTerminal` или `MeshApp.bat`, как описано ниже. Основной `MeshApp.exe` не выводит текст в консоль, из которой его запустили.

## Если вы запускаете приложение из исходников

Установите [зависимости для сборки](../README.ru.md#требования) и откройте терминал в папке проекта.

```bash
# Обычное окно приложения
./gradlew run

# TUI
./gradlew --console=plain runTerminal

# RPC-сервер
./gradlew --console=plain runRpcServer
```

В PowerShell используйте `.\gradlew.bat` вместо `./gradlew`.

Параметры MeshApp передавайте через `--args`. Например, эта команда открывает TUI и подключается к устройству по TCP:

```bash
./gradlew --console=plain runTerminal --args="--host 192.168.1.10"
```

`runTerminal` сам добавляет `--terminal`, а `runRpcServer` — `--rpc-server`. Параметр Gradle `--console=plain` убирает обновляемую строку прогресса, которая мешает работе в терминале.

### Запуск без Gradle

Команда `./gradlew installDist` собирает приложение в папке `build/install/MeshApp`. После сборки его можно запускать напрямую:

```bash
./build/install/MeshApp/bin/MeshApp --terminal
./build/install/MeshApp/bin/MeshApp --rpc-server
```

В Windows сначала выполните `.\gradlew.bat installDist`, затем используйте файл `MeshApp.bat`:

```powershell
.\build\install\MeshApp\bin\MeshApp.bat --terminal
.\build\install\MeshApp\bin\MeshApp.bat --rpc-server
```

Для такой сборки нужна установленная Java 25.

## TUI

В примерах дальше для краткости написано `MeshApp`. Заменяйте это имя командой для своей установки из разделов выше.

При запуске с `--terminal` вы увидите сохранённые подключения. Выберите нужное стрелками и нажмите `c`. Можно сразу указать устройство в команде:

```bash
# По сети
MeshApp --terminal --host 192.168.1.10

# По USB
MeshApp --terminal --serial /dev/ttyUSB0 --baud 115200

# По Bluetooth, для устройства с MeshCore Companion
MeshApp --terminal --ble AA:BB:CC:DD:EE:FF --protocol meshcore-companion
```

Укажите один способ подключения: `--host`, `--serial` или `--ble`. MeshApp создаст для него временный профиль и удалит его при обычном выходе из TUI. Для USB в Windows имя порта обычно выглядит как `COM3`, в macOS — `/dev/cu.usbmodem…`. Для BLE нужен адрес или идентификатор устройства в вашей системе.

| Параметр | Что задаёт |
| --- | --- |
| `--host HOST` | Адрес устройства для подключения по TCP. |
| `--port PORT` | TCP-порт устройства. По умолчанию `4403`. |
| `--serial PORT` | Последовательный порт, в том числе USB. |
| `--baud RATE` | Скорость последовательного порта. По умолчанию `115200`. |
| `--ble ADDRESS` | Адрес устройства для подключения по BLE. |
| `--protocol TYPE` | Протокол: `meshtastic` (по умолчанию), `meshcore-kiss` или `meshcore-companion`. |
| `--name NAME` | Имя временного профиля. По умолчанию `Terminal TCP`, `Terminal Serial` или `Terminal BLE`. |
| `--help`, `-h` | Показать справку и выйти. |

`Tab` переключает панели, `PgUp` и `PgDn` листают историю чата. Когда поле ввода сообщения не выбрано, доступны клавиши `?` (справка), `d` (отключиться) и `q` (выйти). Там же можно нажать `/` и ввести команду: например, `/connect 1`, `/channel 0`, `/dm !12345678` или `/quit`.

## RPC-сервер

Сначала откройте обычное приложение, создайте подключение к радиоустройству и включите для него автоподключение. Проверьте, что соединение работает, затем полностью закройте приложение.

Запустите сервер под той же учётной записью:

```bash
MeshApp --rpc-server --print-rpc-key
```

Сервер возьмёт сохранённые настройки и подключит профили, у которых включено автоподключение. Если таких профилей нет, сервер будет работать без подключения к радиоустройству. Параметры `--host`, `--serial` и `--ble` здесь не поддерживаются.

Если ключ доступа ещё не задан, MeshApp создаст его, сохранит и покажет в терминале. При следующих запусках посмотреть ключ можно с помощью `--print-rpc-key`. Используйте этот ключ целиком, включая начало `mra1_`; заменить его произвольным паролем нельзя.

### Подключение с другого компьютера

По умолчанию сервер доступен только на том же компьютере, по адресу `127.0.0.1:44030`. Чтобы разрешить подключения по сети, запустите его так:

```bash
MeshApp --rpc-server --rpc-bind 0.0.0.0 --rpc-port 44030 --print-rpc-key
```

В MeshApp на другом компьютере добавьте подключение **Remote RPC**, выберите **Direct** и укажите IP-адрес компьютера с сервером, порт `44030` и ключ. Адрес `0.0.0.0` нужен только в команде запуска сервера; на клиенте укажите настоящий адрес, например `192.168.1.20`. Если соединение не устанавливается, проверьте, разрешён ли этот порт в межсетевом экране.

Для остановки сервера нажмите `Ctrl+C` в его терминале.

### Параметры сервера

| Параметр | Что делает |
| --- | --- |
| `--rpc-bind ADDRESS`, `--bind ADDRESS` | Задаёт адрес, на котором сервер принимает подключения. По умолчанию берётся сохранённый адрес или `127.0.0.1`. |
| `--rpc-port PORT`, `--port PORT` | Задаёт порт от `1` до `65535`. По умолчанию берётся сохранённый порт или `44030`. |
| `--rpc-key KEY`, `--key KEY` | Задаёт ключ доступа вместо сохранённого. |
| `--rpc-router [SERVER]`, `--rpc-router-server [SERVER]` | Подключает сервер к External RPC Router. Если адрес не указан, используется сохранённый. |
| `--no-rpc-router` | Отключает подключение к Router при этом запуске. |
| `--print-rpc-key` | Показывает ключ доступа в терминале. Новый ключ выводится и без этого параметра. |
| `--no-autoconnect` | Отключает автоматическое подключение к устройствам при запуске. |
| `--help`, `-h` | Показывает справку и завершает работу. |

Адрес, порт и ключ можно передать через переменные окружения `MESHAPP_RPC_BIND`, `MESHAPP_RPC_PORT` и `MESHAPP_RPC_KEY`:

```bash
MESHAPP_RPC_BIND=127.0.0.1 MESHAPP_RPC_PORT=44031 MeshApp --rpc-server
```

Сначала MeshApp ищет значение в параметрах команды, затем в переменных окружения, затем в сохранённых настройках. Если значения нигде нет, он использует настройки по умолчанию или создаёт ключ.

Параметры запуска и переменные окружения не меняют сохранённые настройки. Ключ, который MeshApp создаёт сам, сохраняется для следующих запусков. Параметр `--rpc-server` запускает сервер, даже если он выключен в настройках приложения.

### Подключение через Router

Если прямое соединение недоступно, можно использовать External RPC Router:

```bash
MeshApp --rpc-server --rpc-router --print-rpc-key
```

MeshApp подключится к сохранённому Router. Если адрес не меняли, это `wss://cloud.meshapp.privatepractice.app`. Чтобы указать свой сервер:

```bash
MeshApp --rpc-server --rpc-router wss://router.example.org/rpc --print-rpc-key
```

На клиенте выберите **Router** и укажите тот же адрес и ключ. Сам Router должен быть уже запущен: эта команда только подключается к нему. Прямые TCP-подключения при этом тоже доступны.

Без `--rpc-router` и `--no-rpc-router` MeshApp использует настройку Router, сохранённую в приложении. Описание методов и формата сообщений есть в [документации RPC](rpc-protocol.ru.md).

## Справка и возможные ошибки

Справка вызывается отдельно для TUI и сервера:

```bash
MeshApp --terminal --help
MeshApp --rpc-server --help
```

При запуске через Gradle используйте `./gradlew runTerminal --args="--help"` или `./gradlew runRpcServer --args="--help"`. Команда `MeshApp --help` без указания режима открывает обычное приложение.

Между параметром и его значением ставьте пробел: `--rpc-port 44030`. Запись с `=` не поддерживается. Имена с пробелами заключайте в кавычки: `--name "Home radio"`. Для Gradle: `--args="--host 192.168.1.10 --name 'Home radio'"`.

| Что произошло | Что проверить |
| --- | --- |
| `Unknown terminal option` или `Unknown RPC server option` | Правильно ли написан параметр и подходит ли он выбранному режиму. |
| `Address already in use` | Порт уже занят. Остановите программу, которая его использует, или задайте другой `--rpc-port`. |
| Не удаётся открыть базу данных | Закройте другие запущенные копии MeshApp под этой учётной записью. |
| Нет доступа к USB-порту | См. [инструкцию для Linux](../README.ru.md#linux-доступ-к-usb-serial). |

Все три режима используют одну базу в `~/.meshapp`. Одновременно её может открыть только один процесс. Для запуска сервера и клиента на одном компьютере используйте разные учётные записи.

Параметр `--no-single-instance` (он же `--allow-multiple-instances`) разрешает открыть ещё одно окно приложения. То же делает настройка Java `-Dmeshapp.singleInstance.disabled=true`. Отдельную базу эти параметры не создают.

Коды завершения TUI и RPC: `0` — успешное завершение или показ справки, `1` — ошибка запуска, `2` — ошибка в параметрах.
