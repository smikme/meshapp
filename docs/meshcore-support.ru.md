# Поддержка MeshCore

**Язык:** [English](meshcore-support.md) | Русский | [Deutsch](meshcore-support.de.md)

Реализованы сообщения Companion, редактируемые настройки, контакты, каналы и
расширенные операции. KISS работает как отдельный модемный режим. Есть программные
проверки; полная приёмка на физических радиоустройствах ещё не проведена.

## Подключение

Для Companion-прошивки выберите `MeshCore Companion`. USB/Serial и TCP используют
официальные кадры: компьютер → устройство `3C lengthLE16 payload`, устройство →
компьютер `3E lengthLE16 payload`. Размер payload — до 176 байт. В BLE один payload
передаётся одной GATT-записью/notification без потокового заголовка. Service UUID:
`6E400001-B5A3-F393-E0A9-E50E24DCCA9E`; RX оканчивается на `0002`, TX — на `0003`.
Подписка включается до handshake. Команда не дробится на отдельные GATT-записи;
ошибка записи или превышение известного MTU возвращаются вызывающей операции.

Готовность наступает после корректного SELF_INFO, получения возможностей,
контактов, всех слотов каналов и батареи. Она отличается от открытия транспорта.
Ограниченная очередь выполняет по одной команде с неоднозначным ответом; push
обрабатываются отдельно. После reconnect создаются новая сессия и синхронизация.

## Использование

- Чаты: текст каналов и DM, offline queue, история в H2, повтор того же сообщения.
  `DELIVERED` означает принятие/отправку устройством, `CONFIRMED` — совпавший ACK
  получателя. OK канала не подтверждает приём всеми участниками. Таймаут ACK
  означает отсутствие подтверждения/ошибку. Статус `VERIFIED` не присваивается.
- Текст: DM — 160 байт UTF-8; канал — 160 минус имя отправителя и `: `. После
  третьего повтора DM лимит составляет 158 байт. Проверка есть в поле ввода и
  runtime. Имя автора канального текста не является проверенным открытым ключом.
- Настройки: имя, частота МГц/BW кГц/SF/CR/repeat, мощность дБм, позиция, политики
  объявления и телеметрии, время, PIN BLE и reboot. Где возможно, запись читается
  обратно с устройства.
- Каналы: число слотов из устройства (включая 1/8/40), создание/изменение/очистка,
  Public, hashtag-ключ SHA-256, случайный приватный ключ, ссылки и локальный QR.
- Контакты: полный ключ, тип, флаги/избранное, координаты, время объявления и пути;
  добавление/редактирование/удаление/импорт/экспорт/обмен. Advert/path/delete
  обновляются без reconnect. В настройках доступны удалённые login/logout/status,
  telemetry/CLI и поиск маршрута.
- Расширенный API: tuning, auto-add, статистика/custom vars, scope/hash mode,
  trace, binary/channel/raw/control data, импорт/экспорт/подпись идентичности,
  factory reset. Идентичность и сброс требуют отдельного явного действия.
- Монитор: реальные LOG_RX_DATA записываются как `MESHCORE_RADIO` с RSSI/SNR.
  Команды компьютера и секреты каналов не выдаются за эфирные пакеты.
- KISS: параметры модема, изменение радио/мощности, raw-пакеты до 255 байт,
  TxDone/busy/errors и диагностический SetHardware. Чатов Companion в KISS нет.


## Версии и проверки

Целевая прошивка: [официальный MeshCore](https://github.com/meshcore-dev/MeshCore/blob/81dbae592ffad40b4212bc0b37e82b38da08f4bc/examples/companion_radio/MyMesh.cpp),
commit `81dbae592ffad40b4212bc0b37e82b38da08f4bc`, Companion protocol **14**.
Клиент объявляет версию формата сообщений **3**: прошивка использует её для
V3-конвертов. Это не ограничивает набор команд версией 3. Известные ограничения
версий проверяются до отправки; unsupported/disabled завершают конкретную
операцию и не разрывают сессию. Старые версии целиком не проверены.

[Операции API и параметры](meshcore-api.md) · [Матрица CMD/RESP/PUSH](meshcore-capabilities.md).

| Платформа / транспорт | Программная проверка | Физическое устройство |
|---|---|---|
| Linux TCP | Реальный локальный сокет, независимый эмулятор кадров, reconnect | Не проверено |
| Linux Serial | Adapter, split reads и эталонные кадры; без физического порта | Не проверено |
| Linux BLE | Java-тесты, сборка native-библиотеки, проверки MTU/ошибки записи | Не проверено |
| Windows BLE | Java-тесты; native-код изменён, сборка под Windows не выполнялась | Не проверено |
| macOS BLE | Существующая проверка максимальной записи; Java-интеграция | Не проверено |
| KISS TCP/Serial | Парсер, последовательный handshake, DATA/TxDone/RxMeta | Не проверено |
| JavaFX | Отрисовка пяти вкладок, сохранение имени через сценарный transport | С радио не проверено |

Для аппаратной приёмки нужны два Companion-устройства: канал/DM в обе стороны,
offline queue, совместимость с официальным клиентом, длинный UTF-8-текст,
изменение настроек и восстановление соединения. Зелёный unit-тест этого не заменяет.

## Данные и ограничения совместимости

Миграция H2 до схемы 26 расширяет идентификаторы до 80 символов без пересоздания
истории. Контакт MeshCore — `mc:` и все 64 hex-символа открытого ключа. Локальный
положительный ID сообщения, ACK hash и ID строки БД разделены. Статус обновляется
по строке и владельцу. Сохраняются попытки отправки: номер, hash, таймаут и результат.
Исходные конверты сообщений и имя/fingerprint канала доступны через `message.details`.

Старые короткие ID привязываются к полному ключу в пределах известного владельца,
если prefix однозначен. При совпадении prefix DM не отправляется наугад; входящее
сообщение сохраняется как `mc:pending:<prefix>`. Уже утраченные ключи/сообщения
восстановить нельзя. При конфликте ключей старых счётчиков чтения/списков чатов
вспомогательные строки сохраняются. Секреты исключены из обычных логов и status
RPC, доступны только явным операциям экспорта. H2 не является зашифрованным хранилищем ключей.

Прошивка извлекает сообщение до подтверждения локального сохранения. Клиент
записывает его перед следующим запросом и останавливается при ошибке БД, но не
может гарантировать exactly-once при падении процесса в этом промежутке. Два
одинаковых сообщения от одного отправителя с одинаковым временем протокол не
всегда позволяет различить. При смене канала история слота сохраняется; при
дедупликации учитывается fingerprint ключа канала.

Официальный framing заменяет старую эвристику raw stream. Профиль Companion
сохраняется, но нестандартный мост с голыми payload нужно обновить. Профили без
поля protocol остаются Meshtastic. KISS несовместим с Companion на уровне кадров.

Ссылки и QR используют [формат официального клиента](https://github.com/meshcore-dev/MeshCore/blob/81dbae592ffad40b4212bc0b37e82b38da08f4bc/docs/qr_codes.md).
Ссылка канала с `region_scope` явно отклоняется: scope нужно настроить отдельно.
QR создаётся локально; импорт принимает текст ссылки. Сканирования камерой или
распознавания QR из картинки пока нет.

Расширенные binary/trace/status/statistics доступны исходными payload через
диагностику/API; отдельные формы и графики есть не для всех ответов. Для части
расширенных команд ещё нужны независимые fixtures — это отмечено в матрице.
Meshtastic protobuf replies/reactions по MeshCore не отправляются.
